# dowel-server — модели Базиса на сервере, без Базиса

`dowel-server` — это dowel-craft без окна: командная строка и HTTP API для веб-конструктора мебели.
Работает на Linux-сервере (в том числе в Docker). Конструктор на сайте присылает команды проектирования
(«материал», «корпус», «полка», «перегородка», «дверь», «ящики», «крепёж»…), сервер собирает модель и отдаёт файлы.

## Что отдаёт

| Вид | Что это | Статус |
|---|---|---|
| `cfrn` | Обменная модель БАЗИС-Облака (ZIP + `file.json`). Формат описан «Базис-Центром» (help.bazissoft.ru → «Описание формата файла CFRN»). API БАЗИС-Облака конвертирует его в `.b3d` (`POST /api-cloud-tasks-public/tasks/model-convert`, услуга «АпиЛист») | **основной путь**: официальный формат и официальная конвертация |
| `b3d` | Модель «Базис-Мебельщика», записанная напрямую | **проверить в настоящем Базисе**: в конце настоящих `.b3d` есть 64 байта (вероятно, подпись), dowel-craft их не пишет — открывает ли Базис такой файл, не подтверждено |
| `cut_pdf` | Карты раскроя и карточки деталей | готово |
| `drawings_pdf` | Сборочный чертёж и чертежи деталей | готово |
| `smeta_csv`, `spec_csv` | Расход плиты и кромки, список деталей | готово |
| `raskroy_xml` | Проект для БАЗИС-Раскроя | готово |
| `project` | Проект dowel-craft (`.dcraft`, JSON) | готово |

## Запуск

```bash
docker build -f packaging/server/Dockerfile -t dowel-server .
docker run -d --name dowel-server -p 127.0.0.1:8090:8090 -e DOWEL_TOKEN=секрет -e DOWEL_LANG=ru dowel-server
```

Без Docker: `cargo build --release -p dowel-server`, затем `DOWEL_TOKEN=секрет dowel-server serve --addr 127.0.0.1:8090`.
Наружу сервер выставлять через nginx/caddy с HTTPS. Если задан `DOWEL_TOKEN`, каждый запрос (кроме `/health`)
должен нести заголовок `Authorization: Bearer <токен>`.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/health` | `{"ok": true, "version"}` |
| GET | `/v1/commands` | список команд проектирования с параметрами |
| GET | `/v1/outputs` | список видов файлов |
| POST | `/v1/build` | `{name, parts, results, problems, files: {вид: base64}}` |
| POST | `/v1/b3d`, `/v1/cfrn` | сам файл |

Тело POST:

```json
{
  "name": "Шкаф в прихожую",
  "commands": [
    {"cmd": "material.add", "params": {"name": "ЛДСП Белый 16", "thickness": 16, "article": "W1000"}},
    {"cmd": "edge.add", "params": {"name": "Кромка 2", "thickness": 2}},
    {"cmd": "cabinet.add", "params": {"width": 800, "height": 2000, "depth": 560, "material": "ЛДСП Белый 16", "edge": "Кромка 2"}},
    {"cmd": "shelf.add", "params": {"cabinet": 1, "height": 1000}}
  ],
  "outputs": ["cfrn", "cut_pdf", "smeta_csv"]
}
```

Можно передать готовый проект в поле `project` (JSON `.dcraft`) и дописать к нему команды.
Команды выполняются по порядку; первая ошибочная останавливает сборку — ответ `422` с `command_index` и текстом ошибки.
`problems` — проверка модели: пересечения деталей, крепёж без панели, детали больше листа.

## Что проверить до запуска в работу

1. Открыть в настоящем Базисе (у партнёра-цеха или на офисном ПК) пару файлов: `.b3d` от сервера и `.b3d`,
   полученный из нашего `.cfrn` через БАЗИС-Облако. Сверить детали, кромку, отверстия, пазы.
2. Получить у «Базис-Центра» тариф «АпиЛист» и ключ Public API; уточнить письменно условия автоматической конвертации.
3. Дуги и окружности в CFRN пока пишутся ломаной (32 отрезка на оборот): в образце формата нет полей дуги.
